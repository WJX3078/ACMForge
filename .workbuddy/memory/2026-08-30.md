### agent-browser 测试陷阱（重要，反复踩）

1. **`eval .click()` 点不动 Radix 组件** —— Tabs/DropdownMenu 监听 pointerdown + focus，
   `HTMLElement.click()` 只派发 click 事件。必须派发完整序列
   `pointerdown → mousedown → pointerup → mouseup → click`，或用 `$AB click <sel>` 真实点击。
2. **`text=Solution` 是子串匹配** —— 会命中 sidebar 的 "Solutions" 导航项，点了没反应还以为有 bug。
   用 `[role=tab]:nth-of-type(N)` 之类精确选择器。
3. **`querySelector('[role=tabpanel]')` 拿到的是 inactive 占位槽** —— Radix 给 5 个 tab 都留了节点，
   inactive 的 `childCount:0 / innerLen:0`。必须查 `[role=tabpanel][data-state=active]`。
   我一度因此误判「Tab 点击不切换内容」，实际完全正常。
4. **browser daemon 在脚本之间会丢页面** —— 上一条命令的页面下一条 eval 就是空文档。
   `open` + 断言必须放在**同一个脚本**里。
5. **非 ASCII 路径存不了截图** —— 中文目录报 "系统找不到指定的路径"。用 `C:/Users/asus/xxx` 纯 ASCII 路径。
6. **不能并发跑两个 agent-browser 脚本** —— 所有脚本共用同一个 daemon，并发会互相抢浏览器，
   表现为路由串台（明明 open 了 `#/` 却读到 Settings 内容）、按钮 index 变 -1。必须串行执行。
7. **`performance.getEntriesByType('resource')` 跨 hash 导航累积** —— SPA 内跳转不重置 resource timing，
   导致后一条路由看起来下载了前面所有路由的 chunk。测首屏体积必须强制整页加载：
   `open "$BASE/?r=${RANDOM}#/route"`（唯一 query 触发真实导航）。

## 性能优化：路由级代码分割（本轮实际改动）

原来打包成单个 1,091 kB（gzip 325 kB）chunk。改为：

- `App.tsx`：除 Dashboard 外 11 个页面改 `React.lazy`；`AppShell` 的 `<Outlet>` 包 `<Suspense>`，
  保证切路由时 sidebar / header / Agent Dock 不卸载
- 新增 `components/common/PageFallback.tsx`（骨架屏 fallback，沿用已有 `Skeleton` 原语）
- `Dashboard.tsx`：`ThroughputChart` 改 lazy —— Recharts 只对 dashboard 加载
- `vite.config.ts`：`manualChunks` 拆 react-vendor / radix / motion / icons；
  `chunkSizeWarningLimit` 1200 → 600

**关键坑**：一开始把 recharts 也写进 `manualChunks` 命名为 `charts`，结果 entry chunk 静态
`import{c as ot}from"./charts-xxx.js"`，把 383 kB 拖进**每条路由**的关键路径。
去掉这条规则、让 Rollup 按动态 import 自然分割后正常。
教训：**只被动态 import 依赖的库，不要手动指定 manualChunks**。

实测（`tools/payload.sh`，整页冷加载，gzip）：

| 路由 | 首屏 JS | recharts |
|---|---|---|
| `/` | 288 kB | 加载（确实要渲染图表） |
| `/settings` | 185 kB | 不加载 |
| `/stress` | 185 kB | 不加载 |
| `/problems` | 185 kB | 不加载 |

非 dashboard 路由从 325 kB → **185 kB，降 43%**。

回归：smoke 12/12、responsive 5 断点 0 溢出、tabs-verify 5/5、
stress-interact（#18293 MISMATCH → n=7）、interactions（命令面板 / Drawer / Factory 流水线）全部通过。

## 新增陷阱：`agent-browser eval` 返回的是转义 JSON

返回值形如 `"{\"over\":0,\"mainLen\":2297}"` —— 引号带反斜杠。
直接在 bash 里匹配 `"over":0` **永远匹配不上**，会误判成"每条路由都溢出 + 内容为空"。
必须先 `sed 's/\\"/"/g'` 反转义再断言。我因此误报过一次全量失败。
