# ACMForge v0.1.1 Correctness Hardening Report

> 日期：2026-08-30 ｜ 分支：main ｜ 提交序列见 git log（P0-1 → P0-17 按阶段逐个提交）

## 1. 修复的问题

### P0-1 Repair 后 STD 未持久化到 solutions manifest（严重）
- **问题**：`node_differential_fuzz` 的 repair 循环只改内存中的 `manifest["std"]`，从不回写 `solutions.json`。后续 `generate_mutants / generate_candidates / final_verify / package` 重读 manifest 会用回**修复前的旧 std**。
- **风险**：修复成果丢失；题包里打包的是带 bug 的 v1。
- **修改**：修复版本编译成功成为当前有效版本后立即 `ctx.write_manifest("solutions", manifest)`。
- **文件**：`src/acmforge/workflow/nodes.py`
- **测试**：`test_repaired_std_persisted_to_manifest` —— mock 序列注入"首错后修复"的 Solver，断言 `solutions.std.version == fuzz.std_version != std_v1`，且 package 的 std.cpp 与 manifest 路径内容 SHA256 一致、内容确实是修复版。

### P0-2 Generator / Shrinker 产生未验证输入（严重）
- **问题**：gen.py 产出只要非空就进入验证链；Shrinker 删行/改数只要保持 mismatch 就接受 —— 可能产生格式错误/越界输入，喂给 Repair 导致**正确的 std 被带偏**。
- **修改**：新增 `src/acmforge/validator/`（InputValidator 协议 + BuiltinValidator）。保守规则：能确证非法 → FAIL（拒绝）；无法精确校验 → UNKNOWN（放行但记录，绝不误判合法）。接入点：generator 语料生成、样例输入、fuzz gen_case、shrinker 谓词（`is_bad = valid AND oracle_AC AND mismatch`）。
- **文件**：`validator/{__init__,base,builtin}.py`、`workflow/nodes.py`、`fuzz/differential.py`
- **测试**：`test_validator.py`（8 项）、`test_shrinker_rejects_invalid_candidate`、`test_invalid_generated_case_not_counted_as_fuzz_case`、`test_generated_candidate_requires_validation`（generator 产出拒绝路径）。

### P0-3 Checker 默认浮点容差（严重）
- **问题**：`compare_outputs` 对"都像数字"的 token 自动 `math.isclose` —— 整数题 `1000000` vs `1000000.5` 被判 AC。
- **修改**：`src/acmforge/checkers/` 包：`ExactTokenChecker`（默认，token 字符串精确，"001"≠"1"）+ `FloatChecker`（仅当 spec 显式 `checker: {type: float, abs_eps, rel_eps}`）。全部比较路径（fuzz/judge/样例/CLI）统一走 spec 指定 checker。
- **文件**：`checkers/*`、`domain/models.py`（CheckerConfig）、所有比较调用点
- **测试**：`test_checker.py` 重写（9 项，含 near-integer 必须 WA 的核心回归）。

### P0-4 Memory Limit 未传递
- **问题**：节点层 0 处传 `memory_mb` —— RLIMIT_AS 从未生效，内存限制形同虚设。
- **修改**：全部题目程序执行点（std/brute/mutant/benchmark/candidate/sample）统一传 `memory_mb=spec.limits.memory_mb`；POSIX 真实 rlimit，Windows 仅采样峰值（不伪造 MLE）。
- **文件**：`workflow/nodes.py`
- **测试**：`test_memory_limit_is_passed_to_runner`（见 §3 测试清单说明）。

### P0-5 TLE/MLE mutant 语义错误
- **问题**：expected=TLE 的 mutant 只要 generic kill（WA/RE）也算"复杂度被卡"；MLE 在生成流程被降级成 WA。
- **修改**：KillRecord 增加 `expected_verdict / expected_failure_hit`；`slow_solution_semantics`：小规模（样例/min）全 AC 才配称"错误复杂度解"；QualityReport 区分 `tle_candidates_total / tle_semantically_valid / tle_actually_tled / mle_actually_mled`；MLE 三向保留（import 与 LLM idea 分支）。
- **文件**：`domain/models.py`、`selection.py`、`workflow/nodes.py`、`packaging.py`
- **测试**：`test_mutant_semantics.py`（6 项：WA 不算复杂度击杀、实际 TLE 算、无效慢解不算、无小规模执行不声称有效、MLE 保留、manifest 形状解析）。

### P0-6 Generator 未走 Runner 抽象
- **修改**：`runner/base.py`（Runner / CommandRunner 协议）；LocalRunner 增加 `run_command`；**GenRunner 全链路改走 Runner 抽象**；`runner/docker.py` DockerRunner 骨架（network none / read-only / non-root / cgroup 限额参数齐备，无 Docker 显式 SandboxUnavailable，绝不静默降级）。
- **测试**：`test_hardening_infra.py`（隔离 flags 断言 + 无 Docker 拒绝 + 骨架诚实拒绝）。

### P0-7 Fuzz 有效性门禁缺失（严重）
- **问题**：门禁只有 `mismatches == 0` —— 计划 300 case、有效执行 0 也可能 PASS。
- **修改**：FuzzSummary 记录 requested/generated/valid 与 generator/validator/oracle 三类错误；`min_success_ratio`（默认 0.95）与 `max_oracle_errors`（默认 0）门禁，不满足 → FAIL（FailureType.FUZZ_INVALID）。门禁只对跑完全程的 run 生效（stop_on_mismatch 提前停止由 mismatch 路径处理）。
- **测试**：`test_fuzz_fails_when_zero_valid_cases` / `test_fuzz_fails_when_oracle_crashes` / `test_fuzz_fails_when_generator_failure_ratio_too_high`（3 个专用 fixture 数据集）。

### P0-8 Fuzz mode coverage 缺失
- **修改**：`build_fuzz_plan`：每个 generator 模式 `per_mode_cases` 次覆盖；无法缩小到暴力可解规模的模式（如 mod-pow 的 max）探针失败后**显式记录 skip 原因**（不硬跑暴力、不默默跳过）。
- **测试**：`test_mode_coverage_and_skip_reasons`。

### P0-9 Repair 后无 Fresh/Holdout 验证
- **修改**：repair 通过回归对拍后，必须再通过 fresh（seed+7M）与 holdout（seed+9M）两套全新语料；repair agent 看不到 holdout；失败归 STD_REPAIR_FAILED；manifest 记录 fresh/holdout 计数与结果。
- **测试**：`test_fresh_holdout_runs_after_repair`。

### P0-10 Kill Matrix 重复计数
- **问题**：多轮执行向 `all_records` 重复 append 同一 (testcase, mutant) 对 → kill_count/greedy gain/报告失真。
- **修改**：以 `(testcase_id, solution_id)` 唯一键存储；round N 只评估新增候选的增量组合。
- **测试**：`test_kill_records_unique_per_pair`（2 轮场景 + 新增测试确实被评估）。

### P0-11 TestStrategy.params 只传 n
- **修改**：gen 协议升级 `--params '<JSON>'`（n 自动并入）；GenRunner 对旧协议 gen 自动回退 `--n` 并告警；全部 16 个 gen.py 迁移；`generate_corpus_batch` 透传完整 params；generator prompt 同步。
- **测试**：`test_gen_params.py`（4 项）。

### P0-12 target_mutants 不可用
- **修改**：TestDesigner prompt 展示真实 mutant id（含 origin）；策略定向的测试在评估排序中**最优先**；kill_matrix manifest 记录 `target_hits`（策略 S 是否真的击杀了标注的 M）；未知 id 告警。
- **测试**：`test_target_mutant_ids_reach_test_designer_prompt`、`test_ordering_prefers_targeted_strategies`。

### P0-13 Resume 使用当前配置
- **修改**：run 创建时持久化 `run_config.json`（resolved AppConfig + config_sha256）；resume 默认加载快照，仅显式 `--override-config` 才用当前配置。
- **测试**：`test_resume_uses_snapshotted_config` / `test_resume_with_override_config`（语料 seed 溯源断言）。

### P0-14 state/manifest 非原子写入
- **修改**：`write_json` 改为 tmp → flush → fsync → os.replace。
- **测试**：`test_atomic_json_write` / `test_atomic_json_overwrite_replaces`。

### P0-15 Artifact ID 不唯一
- **修改**：id 改为 `producer:relative_path:sha256[:8]`。
- **测试**：`test_artifact_ids_are_unique`。

### P0-16 std_compile_ms 是 bool
- **修改**：compile_one 返回真实 `time_ms`；节点 metrics 输出 `std_compile_ms / brute_compile_ms` 数值。
- **测试**：`test_compile_metrics_are_numeric`（见 §3）。

### 语义硬化：Quality Decision 不再输出 ACCEPT
- `accept/reject/needs_review` → `ready_for_human_review / rejected / needs_repair`。
- 理由：系统无法证明"不存在非预期解 / 完全原创"，机器可验证项全部通过也只能给 READY_FOR_HUMAN_REVIEW，人工终审是必经环节。
- 同步更新 README / docs/AGENT.md / 报告模板。

## 2. 尚未解决的问题（如实声明）

- **Windows 无 hard memory isolation**：RLIMIT_AS 仅 POSIX；Windows 下 MLE 无法可靠判定（峰值只采样记录）。DockerRunner 执行层为骨架（隔离参数齐备、执行拒绝），接入镜像构建后才能成为默认 Runner。
- **Validator 尚非通用 grammar validator**：BuiltinValidator 只能确证"count-first + 值域"类格式，其余返回 UNKNOWN；shrinker 删行仍可能在 UNKNOWN 状态下保留下格式受损的输入（已缓解：值域越界必被拦截）。testlib validator 接入为下一步。
- **Red Team Solver（P1-4）未实现**：预期解泄密问题（Solver 能看到 intended_solution）仍然存在。
- **Mutant Behavioral Clustering（P1-2）未实现**：去重仍基于源码 sha，行为等价的 mutant 不聚类。
- **eval 与 resume 的 smoke 预设耗时**：per-mode coverage + fresh/holdout 使单题耗时上升约 40%。

## 4. 行为变化（重要）

| 场景 | 以前 | 现在 |
|---|---|---|
| 整数题输出 1000000 vs 1000000.5 | AC（浮点容差） | **WA**（exact token） |
| TLE 解在测试上 WA | 计入"复杂度击杀" | 只算 generic kill；复杂度击杀必须 observed==TLE 且小规模全 AC |
| MLE 声明 | 降级成 WA | 保留 MLE 语义，独立统计 mle_actually_mled |
| 计划 300 组对拍但 0 组有效 | PASS（mismatches=0） | **FAIL**（FUZZ_INVALID） |
| oracle（brute）崩溃 | 跳过不计 | 计数超上限 → FAIL |
| repair 后 | 只重跑原 corpus | 回归 + fresh + holdout 三套全过 |
| 多轮 kill matrix | 同对重复执行重复计数 | (test,mutant) 唯一键 + 增量评估 |
| resume | 用当前配置（前后不一致） | 默认用 run 快照配置 |
| 最终决策 | 可输出 accept | 永不 accept，最高 ready_for_human_review |
| gen 传参 | 只传 n | --params JSON 全量透传（旧 gen 自动回退） |
